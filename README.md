# Data Guard AI

A multi-agent data quality pipeline with a web interface. Upload a CSV, it detects missing values, duplicate rows, and outliers, cleans them automatically, scores the dataset before and after, and explains what it did and why.

## Stack

- **Backend:** FastAPI (Python)
- **Frontend:** HTML, CSS, JavaScript — no framework, no build step
- **LLM:** Featherless AI for the explanation layer, with a rule-based fallback when no API key is set or the call fails

## How it works

The pipeline runs nine stages in sequence:

1. **Ingestion** — loads and validates the uploaded CSV
2. **Profiling** — detects column types (numeric vs categorical)
3. **Quality Check** — finds missing values, duplicate rows, and outliers (IQR method)
4. **Repair Advisor** — decides the fix for each issue: mode for categorical, median for numeric, IQR capping for outliers
5. **Planner** — builds an ordered repair plan, skipping steps that aren't needed
6. **Executor** — applies the fixes and logs every change
7. **Scorer** — computes a 0–100 quality score, run once before and once after cleaning
8. **Explainer** — writes a column-by-column explanation of what was wrong and what was fixed
9. **Monitor** — tracks API usage, response time, and errors for the explanation step

## Project structure

```
backend/
  main.py              FastAPI routes
  agents/               the nine pipeline stages, one file each
  core/                 pipeline orchestration, shared data models
  .env.example          copy to .env and add your Featherless key
frontend/
  index.html
  app.js
  styles.css
test_sales.csv          sample dataset to try it with
```

## Running it locally

**Backend**
```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

**Frontend** (separate terminal)
```bash
cd frontend
python -m http.server 5500
```

Open `http://localhost:5500`, upload a CSV, run the pipeline.

To use Featherless AI for the explanation step, copy `backend/.env.example` to `backend/.env` and add your key. Without it, explanations are generated by the rule-based fallback — the app works either way.

## Notes

- The executor never modifies the original data in place — it works on a copy, so the source is always recoverable.
- Order matters during repair: duplicates are removed first, then outliers are capped, then missing values are filled — so the fill statistics aren't skewed by duplicate rows or extreme values.
- CORS is wide open by default for local development. Restrict `allow_origins` in `backend/main.py` before deploying publicly.
